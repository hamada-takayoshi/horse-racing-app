# コマンド実行ポリシー

## 目的

通常の開発コマンドごとに毎回事前確認や`git status`を行わず、明示された作業を進める。一方、DBデータ・作業内容・永続設定を破壊または外部公開する操作は、事前に利用者の許可を得る。

このポリシーは、利用者が依頼した作業の範囲内で適用する。確認不要の一覧は、依頼されていない機能追加や対象拡大を許可するものではない。

## 通常の事前確認が不要な操作

以下は対象と副作用が依頼範囲内である限り、個別の実行確認を求めずに実行してよい。

| 操作・コマンド例 | 適用条件 |
|---|---|
| PowerShellの読み取り専用ファイル検査 | `Get-Content`、`Select-String`、`Test-Path`などで対象パスを限定し、結果を端末へ表示する検査。変数代入、条件分岐、ループ、パイプラインを含んでも、すべての処理が読み取り専用なら確認不要。秘密情報の値は出力しない。ファイル変更・削除、レジストリ変更、外部通信、任意プログラムの実行を含む場合は対象外。 |
| `git status --short --branch` | 作業ツリーとブランチの状態確認。読み取り専用のため、確認なしで実行してよい。定型作業で毎回実行する必要はない。 |
| `dotnet restore HorseRacing.sln` | NuGet依存関係の復元。依存パッケージの追加自体は、依頼された実装に必要な場合に限る。 |
| `dotnet build HorseRacing.sln --no-restore` | ソリューションのビルド。 |
| `dotnet test HorseRacing.sln --no-restore` | ソリューションのテスト。 |
| `git diff --check` | 空白・差分形式の検査。 |
| `git diff -- <明示したパス>` | 指定パスの未ステージ差分の閲覧。 |
| `git diff --cached --check` | ステージ済み差分の空白・差分形式の検査。 |
| `git diff --cached -- <明示したパス>` | 指定パスのステージ済み差分の閲覧。 |
| `git add -- <明示したパス>` | 利用者がコミットを依頼した場合に限る。広域指定を使わず、対象パスを列挙する。 |
| `dotnet run --project src/HorseRacing.App/HorseRacing.App.csproj --no-launch-profile --urls http://127.0.0.1:<port>` | ローカル動作確認に限る。待受先は`127.0.0.1`または`localhost`とし、LANへ公開しない。 |

通常の編集、ビルド、テストの前提条件として`git status`を毎回実行しない。必要なファイルや設定の存在は、対象を指定した確認で調べる。

## 利用者の明示的な依頼が必要な操作

以下は一覧にあるコマンドでも、実行内容に対する利用者の明示的な依頼なしに実行しない。

| 操作 | 対象例 |
|---|---|
| DBデータの削除・初期化 | `database/scripts/reset-db.ps1`、`docker compose down -v`、DB/テーブルの`DROP`・`TRUNCATE`、広範囲の`DELETE` |
| 作業内容の一括破棄・強制変更 | `git reset --hard`、`git clean`、既存ファイルを上書きする`git checkout`/`git restore`、強制push |
| 外部公開 | `0.0.0.0`やLANアドレスでの待受、LAN/インターネットへのデプロイ、外部サービスへのデータ送信 |
| 永続的な環境変更 | システム全体へのインストール、ユーザー/システムPATHやPowerShellプロファイルの変更、証明書の信頼設定 |
| コミット・push | 利用者がコミットまたはpushを依頼した場合に限る。force pushは別途明示指定がない限り実行しない。 |

利用者が操作を明示的に依頼した場合は、その依頼範囲だけを実行する。確認不要一覧にないオプションを追加して破壊範囲・公開範囲を広げない。

## Gitの確認方法

- `git status`は読み取り専用であり、通常作業の必須ゲートにしない。
- コミットを依頼された場合は、コミット前に`git diff --cached --name-status`とステージ済み差分を確認し、依頼対象外の変更を含めない。
- 利用者の変更を無断で破棄・上書きしない。対象や副作用が不明な場合は、実行を止めて確認する。

## 一覧外のコマンド

一覧外でも、依頼範囲内の通常の読み取り・ビルド・テスト・限定的なファイル作成は、挙動が明確なら進めてよい。DBデータ、既存作業、永続設定、外部公開に影響する可能性がある、または副作用を判断できない場合は、実行前に確認する。
